# PRAHARI

**SIH 2026 · Problem Statement 26152 (Social Media Analytics) · NTRO · Theme: Blockchain & Cybersecurity**
**Team MOGGERS — VIT Pune**

> **PRAHARI** (प्रहरी, "sentinel")
> is a next-generation, privacy-first intelligence platform engineered to detect coordinated inauthentic
> behavior and sophisticated disinformation campaigns across major platforms including X (Twitter), Telegram, Reddit, and YouTube.
> Built with military-grade tamper-evident ledgers, advanced behavioral heuristics, and k-anonymized demographic analysis,
> PRAHARI empowers analysts with real-time, actionable insights while maintaining uncompromising ethical standards and data integrity.

**Live demo (public, read-only, synthetic data):** https://prahari-h849.onrender.com  
**Code:** https://github.com/Shantanu58-tech/PS_2

**Core idea: coordination-adjusted analytics.** Every view (sentiment, trends,
demographics, influence) can be shown *raw* or *organic-only*, with coordinated
accounts removed, so an analyst can see how much a campaign distorted the picture.
Every collected record is hash-chained into an append-only evidence ledger.

prompt-injection defences.

## Quickstart

Requirements: Python 3.11, Node 20. On Windows use `scripts\dev.ps1 <target>` in place of `make <target>`.

```bash
make setup                 # backend venv deps + frontend npm install
cp .env.example backend/.env
make models                # download the pre-trained models into ./models (~2.5 GB)
make scenario              # synthetic 7-day scenario -> replay/ (+ data/media)
make demo                  # builds the console and serves UI + API on http://localhost:8000
```

Open http://localhost:8000, then click **Load data** on the Overview page.
Replay ingests about 37k records through the ledger, and the analytics run automatically.
Then:

```bash
make test                  # 135+ tests (fast fallbacks; no model download needed)
make eval                  # full evaluation -> eval/reports/summary.json (~30 min on CPU)
make verify                # independent ledger verification
make check-collectors      # one live pull per collector with credentials in .env
```

Docker: `docker compose up --build` gives one image with the UI and API on port 8000.

Hosted demo: https://prahari-h849.onrender.com (Render free web service, read-only demo mode, kept awake by a Cloudflare cron Worker; see `deploy/render/README.md`).

### Live collectors
Put credentials in `backend/.env` (see `.env.example`), add targets with
`POST /api/collectors/{x|telegram|reddit|youtube}/targets?target=...`, and run with
`MODE=live`. Test each one first with `python scripts/check_collectors.py <name>`.
Telegram asks for your phone login code once, interactively.

## Architecture

```
Collectors (X, Telegram, Reddit, YouTube, IG/FB import, Replay)
   -> RawRecord -> Ledger writer (canonical JSON -> SHA-256 chain -> signed Merkle checkpoints)
   -> Normaliser -> SQLite (WAL, FTS5): posts, accounts, edges, media
   -> Analytics: emotions -> topics -> coordination -> series/bursts -> demographics
                 -> behaviour -> forecasts -> Signal Cards -> OpenTimestamps anchor
   -> FastAPI (REST + SSE) -> React console (same origin)
```

Each prototype component sits behind an interface (Collector, Queue, GraphStore
[NetworkX or Neo4j], ledger), so a production swap is a configuration change.

## Honest limitations

1. **The demo data is synthetic** (fictional places, accounts and events, all marked `synthetic=true`). The collectors are live-capable, but running them needs platform credentials.
2. **Emotion is our weakest component.** Metrics use synthetic template labels (about a dozen distinct texts), not a human-audited gold set (*not yet measured*). The zero-shot model keys on words like "panic" rather than meaning: it scores a debunk ("Stop spreading panic") as more panicked than the rumour itself, so the raw-vs-organic anxiety distortion is currently inverted (x0.69) and must not be claimed. Sarcasm is weak (F1 0.17). The PRD 11 MuRIL fine-tune is the fix.
3. **Coordination weights were tuned on one synthetic seed.** Real campaigns vary cadence and content, so expect lower recall on real data. Scores are a signal for review, not an accusation.
4. **Lineage reports the *earliest observed* origin**, which may not be the true origin.
5. **Age inference is coarse**, using bio cues only, and covers few accounts.
6. **The §63 certificate is a draft** for counsel review. No admissibility is claimed.
7. **CPU inference is slow on first run**: roughly 5 minutes of emotion scoring for the demo scenario. Scores are cached afterwards.
8. **Not yet implemented:** JWT login, rate limiting, CSP headers (see SECURITY.md), OCR and CLIP image search (P1), and an ONNX export.
